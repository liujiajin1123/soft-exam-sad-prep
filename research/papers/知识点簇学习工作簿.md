# 系统架构师论文知识点簇学习工作簿

> **用途：**把历年论文知识点按可复用原理分簇，逐步填写“是什么、为什么、怎么运行、何时使用、与谁易混、如何结合项目表达”。这是可编辑的工作底稿，不是完成版知识讲义或官方分类。允许持续新增、删减、拆分、合并知识点和知识簇。
>
> **填写原则：**先保持结构轻量；每次重点完善少量知识点。先核准概念和来源，再写项目论证；不会或未核验的内容明确标成待学/待核，不要用猜测填满空格。

> **先修学习路线（按理解依赖，而非押题频率）：**
>
> 1. **系统设计基础：**结构化分析/设计 → 架构生命周期/演化 → ABSD → 架构评估；并行入门Scrum/敏捷和软件维护，建立“项目如何开发、交付、变化”的背景。
> 2. **系统集成与服务：**企业集成平台/多源数据集成 → 构件开发 → SOA → 微服务；随后学习事件驱动及Serverless，区分服务边界、通信方式和运行托管方式。
> 3. **数据专题：**数据集成基础 → Lambda批流处理 → 数据湖/数据仓库 → 湖仓一体；随后分别学习多模型、云原生、向量数据库和图数据，避免把不同存储模型混成一类。
> 4. **分布式与安全：**网络/一致性/故障处理基础 → 边云协同和区块链；安全架构作为贯穿所有架构专题的约束单独建立基础卡。
> 5. **运维与性能：**运维生命周期/CloudOps/云原生运维 → 云数据库容量 → Serverless弹性 → 秒杀流量治理；让容量设计连接到压测、限流、降级和恢复。
> 6. **智能测试：**先学测试流程和质量度量 → AI测试用例生成 → 多模态移动测试，重点理解AI模块的校验、人工复核、失败回退和效果指标。
>
> 每轮只学一个簇或两三个紧密相关的概念。第一目标是能用自己的话说清并画出基本流程；确认理解后再写项目段。若需要按考试日期倒排，再据实际可用时间压缩路线。

## 6. 调整分类的规则

1. **拆簇条件：**一个簇内知识点共同原理很弱、比较表越来越长，或复习时需要完全不同的先修知识/答题框架时，考虑拆分。
2. **合簇条件：**两个簇只有名称不同、核心问题和主卡几乎相同，且差异可用专题卡清楚表达时，考虑合并。
3. **保留交叉标签：**跨簇知识用“主簇+关联簇”标记，不要因为一题涉及多种技术就复制多份冲突笔记。
4. **区分题目证据和知识解释：**题目截图能证明题干出现过某主题；不能单独证明技术原理正确。技术知识另找教材/标准/可靠资料核验。
5. **保留旧版和变更原因：**调整簇名、合并拆分、纠正定义时记录日期、原因和影响的题目/笔记链接。
6. **先问能否解释，再判是否掌握：**“看过/背过”不算能用；至少能闭卷解释问题、机制、边界、失败和项目证据，才标熟悉度3或4。
